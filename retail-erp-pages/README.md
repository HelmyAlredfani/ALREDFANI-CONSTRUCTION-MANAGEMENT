# ALREDFANI RETAIL ERP — GitHub Pages Edition

واجهة عربية RTL لإدارة المتجر، تعمل على GitHub Pages وتتصل بـ Supabase Auth وPostgres.

## الاتصال
- Project URL: `https://isvnrpylwgenkqaknmhx.supabase.co`
- يستخدم المتصفح Publishable key فقط؛ لا تضع Secret key أو كلمة مرور قاعدة البيانات في المستودع.
- سجّل دخول المستخدم من شاشة الدخول باستخدام حساب Supabase Auth المرتبط بمساحة العمل.

## إعداد قاعدة البيانات السحابية (مطلوب قبل النشر)
1. افتح Supabase → SQL Editor.
2. نفّذ الملف `supabase/migrations/001_workspace_snapshots.sql` مرة واحدة.
3. تأكد أن المستخدم عضو في مساحة العمل بدور `owner` أو `manager`.
4. انشر فرع `retail-cloud-integration` إلى بيئة اختبار Pages، ثم اختبر الدخول والحفظ والاسترجاع.

## وظائف الواجهة الحالية
- لوحة التحكم، المنتجات، نقطة البيع، الفواتير والطباعة.
- المخزون والحركات، العملاء، الموردون، المصروفات، التقارير.
- النسخ الاحتياطي المحلي JSON وCSV.
- تسجيل الدخول عبر Supabase Auth.
- حفظ واستعادة نسخة بيانات مساحة العمل عبر جدول `workspace_snapshots` مع RLS.

## حدود المرحلة السحابية الأولى
هذه مرحلة انتقالية تحفظ حالة بيانات الواجهة كوثيقة JSONB واحدة لكل مساحة عمل. لا تكتب بعد إلى الجداول التشغيلية المنفصلة `products`, `sales`, `sale_items` وغيرها. لذلك:
- لا تستخدم الحساب نفسه بالتزامن من عدة أجهزة أو متصفحات؛ قد تستبدل كتابة أحدث نسخة أقدم.
- لا تدعم بعد صلاحيات الكاشير؛ الحفظ متاح للمالك والمدير فقط.
- عمليات البيع داخل وثيقة البيانات ليست بعد معاملات مخزون خادمية متعددة السجلات.
- لا تعتبر هذه المرحلة نظام ERP متعدد المستخدمين جاهزاً تجارياً.

المرحلة التالية المطلوبة هي نقل كل عملية إلى الجداول الطبيعية وإضافة RPC معاملات للبيع والشراء والتسوية، مع اختبارات تعارض وتزامن وصلاحيات.

## الملفات

- `assets/styles.css`: التصميم.
- `assets/app.js`: وظائف ERP الحالية.
- `assets/supabase-cloud.js`: مصادقة Supabase وحفظ واستعادة النسخة السحابية.
